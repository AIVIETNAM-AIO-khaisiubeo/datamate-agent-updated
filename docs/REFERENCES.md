# Curated Research and Technical References

This list is intentionally shorter than the earlier bibliography. It keeps papers that directly inform methods implemented in the repository, plus a few technical references for the configured model, serving engine, data engine, and lunar-calendar fallback. Works about methods not used in the round-one inference path—such as Monte Carlo Tree Search, unrelated table-reasoning systems, and RL fine-tuning objectives—are omitted.

Citation numbers are retained where they are referenced by source-code docstrings and existing design notes. Gaps are intentional; they do not indicate missing sections.

## Core method inspirations

- **[R3] DIN-SQL — decomposition and self-correction.** Mohammadreza Pourreza and Davood Rafiei. “DIN-SQL: Decomposed In-Context Learning of Text-to-SQL with Self-Correction.” NeurIPS 2023. [arXiv:2304.11015](https://arxiv.org/abs/2304.11015). Context for separating question analysis into smaller, explicit decisions; DataMate performs most of this analysis deterministically.
- **[R7] CHESS — contextual schema and value selection.** Shayan Talaei, Mohammadreza Pourreza, Yu-Chen Chang, Ameen Saberi, and others. “CHESS: Contextual Harnessing for Efficient SQL Synthesis.” [arXiv:2405.16755](https://arxiv.org/abs/2405.16755). Relevant to using schema and database values as context; DataMate uses per-shop role inference and direct matching rather than reproducing CHESS.
- **[R8] CHASE-SQL — diverse candidate generation and selection.** Mohammadreza Pourreza et al. “CHASE-SQL: Multi-Path Reasoning and Preference Optimized Candidate Selection in Text-to-SQL.” ICLR 2025. [arXiv:2410.01943](https://arxiv.org/abs/2410.01943). Inspiration for plan-based generation, candidate diversity, and selection. DataMate uses a lighter selection strategy and does not reproduce its full multi-agent pipeline.
- **[R11] Self-Consistency.** Xuezhi Wang et al. “Self-Consistency Improves Chain of Thought Reasoning in Language Models.” ICLR 2023. [arXiv:2203.11171](https://arxiv.org/abs/2203.11171). Motivation for sampling multiple candidates and looking for agreement; DataMate compares normalized execution results.
- **[R12] ReAct.** Shunyu Yao et al. “ReAct: Synergizing Reasoning and Acting in Language Models.” ICLR 2023. [arXiv:2210.03629](https://arxiv.org/abs/2210.03629). Inspiration for iterative data exploration through tool calls.
- **[R13] CodeAct.** Xingyao Wang et al. “Executable Code Actions Elicit Better LLM Agents.” ICML 2024. [arXiv:2402.01030](https://arxiv.org/abs/2402.01030). Inspiration for Python/pandas as an executable candidate family.
- **[R16] Execution-guided decoding.** Chenglong Wang et al. “Robust Text-to-SQL Generation with Execution-Guided Decoding.” [arXiv:1807.03100](https://arxiv.org/abs/1807.03100). Background for using execution outcomes to reject or repair candidate programs.
- **[R17] Self-Debugging.** Xinyun Chen, Maxwell Lin, Nathanael Schärli, and Denny Zhou. “Teaching Large Language Models to Self-Debug.” ICLR 2024. [arXiv:2304.05128](https://arxiv.org/abs/2304.05128). Background for repair attempts using execution feedback.
- **[R19] TrustSQL.** Gyubok Lee, Woosog Chay, Seonhee Cho, and Edward Choi. “TrustSQL: A Reliability Benchmark for Text-to-SQL Models with Diverse Unanswerable Questions.” [arXiv:2403.15879](https://arxiv.org/abs/2403.15879). Motivation for reliable handling of infeasible questions and penalty-aware evaluation.
- **[R22] PRACTIQ.** M. Dong, N. Ashok Kumar, and others. “PRACTIQ: A Practical Conversational Text-to-SQL Dataset with Ambiguous and Unanswerable Queries.” NAACL 2025. [arXiv:2410.11076](https://arxiv.org/abs/2410.11076). Context for ambiguity and evidence-based unanswerable handling.
- **[R25] AmbiQT.** A. Bhaskar et al. “Benchmarking and Improving Text-to-SQL Generation under Ambiguity.” EMNLP 2023. [arXiv:2310.13659](https://arxiv.org/abs/2310.13659). Context for treating ambiguous entity matches as a distinct reliability signal.
- **[R27] Chow's reject rule.** C. K. Chow. “On Optimum Recognition Error and Reject Tradeoff.” IEEE Transactions on Information Theory, 16(1):41–46, 1970. The theoretical basis for answering only when estimated correctness probability exceeds 0.5 under +1 / −1 / 0 scoring.
- **[R28] Selective classification.** Yonatan Geifman and Ran El-Yaniv. “Selective Classification for Deep Neural Networks.” NeurIPS 2017. [arXiv:1705.08500](https://arxiv.org/abs/1705.08500). General background on prediction with a reject option.
- **[R29] Confidence calibration.** Chuan Guo, Geoff Pleiss, Yu Sun, and Kilian Q. Weinberger. “On Calibration of Modern Neural Networks.” ICML 2017. [arXiv:1706.04599](https://arxiv.org/abs/1706.04599). General calibration background; DataMate uses a supervised correctness calibrator over pipeline features.
- **[R39] Trace Inversion.** Abinitha Gourabathina, Inkit Padhi, Manish Nagireddy, Subhajit Chaudhury, and Prasanna Sattigeri. “Answering the Wrong Question: Reasoning Trace Inversion for Abstention in LLMs.” ACL 2026, Long Papers, pp. 13307–13324. [ACL Anthology](https://aclanthology.org/2026.acl-long.608/) · [arXiv:2604.02230](https://arxiv.org/abs/2604.02230). DataMate adapts the query-misalignment idea to the winning executable program, output preview, and deterministic structural checks; it does not reproduce the original reasoning-trace setup exactly.
- **[R40] ReViSQL.** Yuxuan Zhu, Tengjun Jin, Yoojin Choi, and Daniel Kang. “ReViSQL: Achieving Human-Level Text-to-SQL.” 2026. [arXiv:2603.20004](https://arxiv.org/abs/2603.20004). DataMate adapts selected inference-time ideas—explicit requirements, candidate-group reconciliation, and multi-sample generation. It does **not** reproduce ReViSQL's expert-curated training set or RLVR fine-tuning and makes no claim to its benchmark results.

## Runtime and implementation references

- **[R32] vLLM / PagedAttention.** Woosuk Kwon et al. “Efficient Memory Management for Large Language Model Serving with PagedAttention.” SOSP 2023. [arXiv:2309.06180](https://arxiv.org/abs/2309.06180).
- **[R34] DuckDB.** Mark Raasveldt and Hannes Mühleisen. “DuckDB: an Embeddable Analytical Database.” SIGMOD 2019 (demo).
- **[R35] Qwen3.** Qwen Team. “Qwen3 Technical Report.” [arXiv:2505.09388](https://arxiv.org/abs/2505.09388). The repository configuration names Qwen3-14B as the intended main model; the documented CPU smoke tests do not validate full-model performance.
- **[R37] Vietnamese lunar-calendar algorithm.** Hồ Ngọc Đức. Technical note describing the Vietnamese lunar-calendar calculation, 2004. Used as a reference for the fallback implementation.
- **[R38] Astronomical algorithms.** Jean Meeus. *Astronomical Algorithms*, 2nd edition. Willmann-Bell, 1998. Background for astronomical date calculations used in lunar-calendar algorithms.

## Scope note

The codebase contains utilities for exporting candidate traces and computing a verifiable reward for possible future training experiments. They are not part of the first-round inference command and do not mean that a fine-tuned model is included. The references above are curated to explain actual design choices and the principal runtime dependencies, not to suggest that every cited method is reproduced end to end.
